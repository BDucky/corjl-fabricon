# Corjl try-it-on: Web-to-Mobile Build Guide (Capacitor)

## 1. Architecture Overview

Corjl try-it-on uses **Capacitor** to wrap the Vue 3 web app into native iOS and Android shells. The architecture is:

```
Vue 3 App (Web)
    ↓ pnpm build → dist/
    ↓ npx cap sync
┌─────────────────────────┐
│  Capacitor Runtime      │
│  ┌───────────────────┐  │
│  │ WKWebView (iOS)   │  │
│  │ WebView (Android) │  │
│  └───────────────────┘  │
│  Native Bridge (JS ↔ N) │
│  Native Plugins         │
└─────────────────────────┘
```

- The web app runs inside a native WebView
- Capacitor provides a JS-to-native bridge for accessing device APIs
- Native plugins (Camera, Filesystem, etc.) are called through JavaScript APIs
- Same codebase serves web, iOS, and Android

## 2. Prerequisites

### macOS (iOS + Android)
- **Node.js** 18+ and **pnpm**
- **Xcode** 15+ (from Mac App Store)
- **CocoaPods**: `sudo gem install cocoapods`
- **Android Studio** Hedgehog+ with:
  - Android SDK 34+
  - Android SDK Build-Tools
  - Android Emulator

### Windows/Linux (Android only)
- **Node.js** 18+ and **pnpm**
- **Android Studio** with same SDK requirements as above

## 3. Initial Setup

### 3.1 Build the Web App

```bash
pnpm build
```

This generates the `dist/` directory with the production build.

### 3.2 Initialize Capacitor (already done)

The project already has `capacitor.config.ts` configured:

```ts
// capacitor.config.ts
import type { CapacitorConfig } from '@capacitor/cli'

const config: CapacitorConfig = {
  appId: 'com.corjl.fabricon',   // legacy bundle ID, kept for app-store continuity
  appName: 'Try-It-On',
  webDir: 'dist',
  // ... plugins config
}
```

### 3.3 Add Platforms

```bash
# Add iOS platform
npx cap add ios

# Add Android platform
npx cap add android
```

This creates `ios/` and `android/` directories with native project scaffolding.

### 3.4 Sync Web Assets

```bash
npx cap sync
```

This copies `dist/` into the native projects and installs native plugin dependencies.

## 4. Development Workflow

### 4.1 Live Reload (Recommended for Development)

```bash
# iOS with live reload
npx cap run ios --livereload --external

# Android with live reload
npx cap run android --livereload --external
```

This serves the Vite dev server and points the native WebView to it. Changes appear instantly without rebuilding.

### 4.2 When to Sync

Run `npx cap sync` after:
- Any `pnpm build` (production assets change)
- Installing/removing Capacitor plugins
- Modifying `capacitor.config.ts`

### 4.3 Opening Native IDEs

```bash
# Open in Xcode
npx cap open ios

# Open in Android Studio
npx cap open android
```

### 4.4 Storage: @capacitor/preferences vs localStorage

| Feature | localStorage | @capacitor/preferences |
|---------|-------------|----------------------|
| Persistence | May be cleared by OS | Persistent (UserDefaults / SharedPreferences) |
| Async | No | Yes |
| Size limit | ~5MB | Practical limit ~10MB |
| Use for | Non-critical cache | Auth tokens, user settings |

```ts
import { Preferences } from '@capacitor/preferences'

// Store
await Preferences.set({ key: 'authToken', value: token })

// Retrieve
const { value } = await Preferences.get({ key: 'authToken' })

// Remove
await Preferences.remove({ key: 'authToken' })
```

## 5. Platform-Specific Configuration

### 5.1 iOS Configuration

#### Info.plist Keys

Add to `ios/App/App/Info.plist` as needed:

```xml
<!-- Camera access -->
<key>NSCameraUsageDescription</key>
<string>Try-It-On needs camera access to capture photos for your designs</string>

<!-- Photo library access -->
<key>NSPhotoLibraryUsageDescription</key>
<string>Try-It-On needs photo library access to import images into your designs</string>

<!-- Photo library write access -->
<key>NSPhotoLibraryAddUsageDescription</key>
<string>Try-It-On needs to save exported designs to your photo library</string>
```

#### App Icons

Place icons in `ios/App/App/Assets.xcassets/AppIcon.appiconset/`:
- 1024x1024 (App Store)
- Required sizes are auto-generated by Xcode

#### Splash Screen

Configure in `ios/App/App/Assets.xcassets/Splash.imageset/` or use `@capacitor/splash-screen` plugin.

### 5.2 Android Configuration

#### AndroidManifest Permissions

Add to `android/app/src/main/AndroidManifest.xml`:

```xml
<!-- Camera -->
<uses-permission android:name="android.permission.CAMERA" />

<!-- Internet (already included) -->
<uses-permission android:name="android.permission.INTERNET" />

<!-- Storage (for older Android versions) -->
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" />
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" />
```

#### Adaptive Icons

Place in `android/app/src/main/res/`:
- `mipmap-hdpi/` through `mipmap-xxxhdpi/` for launcher icons
- Use Android Studio's Image Asset wizard for generating adaptive icons

#### Splash Screen

Configure via `@capacitor/splash-screen` in `capacitor.config.ts`:

```ts
plugins: {
  SplashScreen: {
    launchAutoHide: true,
    androidScaleType: 'CENTER_CROP',
    splashFullScreen: true,
    backgroundColor: '#086674', // Corjl teal
  },
}
```

## 7. Native Plugin Integration

### 7.1 Camera (@capacitor/camera)

```bash
pnpm add @capacitor/camera
npx cap sync
```

Usage with web fallback:

```ts
import { Camera, CameraResultType, CameraSource } from '@capacitor/camera'
import { Capacitor } from '@capacitor/core'

async function takePhoto() {
  if (Capacitor.isNativePlatform()) {
    const image = await Camera.getPhoto({
      quality: 90,
      allowEditing: false,
      resultType: CameraResultType.Uri,
      source: CameraSource.Prompt, // Camera or Gallery
    })
    return image.webPath
  } else {
    // Web fallback: use file input
    return new Promise<string>((resolve) => {
      const input = document.createElement('input')
      input.type = 'file'
      input.accept = 'image/*'
      input.onchange = (e) => {
        const file = (e.target as HTMLInputElement).files?.[0]
        if (file) resolve(URL.createObjectURL(file))
      }
      input.click()
    })
  }
}
```

### 7.2 Filesystem (@capacitor/filesystem)

For local project caching and offline support:

```bash
pnpm add @capacitor/filesystem
npx cap sync
```

```ts
import { Filesystem, Directory, Encoding } from '@capacitor/filesystem'

// Save project data locally
async function cacheProject(projectId: string, data: object) {
  await Filesystem.writeFile({
    path: `projects/${projectId}.json`,
    data: JSON.stringify(data),
    directory: Directory.Data,
    encoding: Encoding.UTF8,
  })
}

// Read cached project
async function loadCachedProject(projectId: string) {
  const result = await Filesystem.readFile({
    path: `projects/${projectId}.json`,
    directory: Directory.Data,
    encoding: Encoding.UTF8,
  })
  return JSON.parse(result.data as string)
}
```

## 8. Building for Production

### 8.1 iOS Production Build

```bash
# Build web assets
pnpm build

# Sync to native
npx cap sync ios

# Open in Xcode
npx cap open ios
```

In Xcode:
1. Select your team in Signing & Capabilities
2. Set the deployment target (iOS 16+ recommended)
3. Product → Archive
4. Distribute App → App Store Connect
5. Upload to App Store Connect for TestFlight/release

### 8.2 Android Production Build

```bash
# Build web assets
pnpm build

# Sync to native
npx cap sync android

# Open in Android Studio
npx cap open android
```

In Android Studio:
1. Build → Generate Signed Bundle/APK
2. Create/select keystore
3. Build AAB (Android App Bundle) for Play Console
4. Upload to Google Play Console

### 8.3 CI/CD Pipeline

```yaml
# Example GitHub Actions workflow
- name: Build Web
  run: pnpm build

- name: Sync Capacitor
  run: npx cap sync

- name: Build iOS (macOS runner)
  run: |
    cd ios/App
    xcodebuild -workspace App.xcworkspace \
      -scheme App \
      -configuration Release \
      -archivePath build/App.xcarchive \
      archive

- name: Build Android
  run: |
    cd android
    ./gradlew bundleRelease
```

The same Vue app serves all platforms. Build once with `pnpm build`, then sync:

```bash

```

```ts

// Check if running natively
if (Capacitor.isNativePlatform()) {

  // Use web fallbacks
```

## 10. Troubleshooting

### CORS Issues
- **Problem**: API calls fail on native but work on web
- **Fix**: Capacitor uses `capacitor://localhost` (iOS) or `http://localhost` (Android). Ensure your API allows these origins, or use the Capacitor HTTP plugin:
  ```bash
  pnpm add @capacitor/core  # HTTP is built-in since Capacitor 4
  ```

### Local Storage Limits
- **Problem**: localStorage data lost after app update
- **Fix**: Use `@capacitor/preferences` for persistent data (see Section 4.4)

### Keyboard Overlap
- **Problem**: Keyboard covers input fields
- **Fix**: Already configured in `capacitor.config.ts` with `Keyboard.resize: 'body'`. For additional control:
  ```ts
  import { Keyboard } from '@capacitor/keyboard'

  Keyboard.addListener('keyboardWillShow', (info) => {
    // Adjust layout
    document.body.style.paddingBottom = `${info.keyboardHeight}px`
  })

  Keyboard.addListener('keyboardWillHide', () => {
    document.body.style.paddingBottom = '0'
  })
  ```

### White Screen on Launch
- **Problem**: App shows white screen before content loads
- **Fix**: Configure splash screen to stay visible until app is ready:
  ```ts
  import { SplashScreen } from '@capacitor/splash-screen'

  // In App.vue onMounted
  await initializeApp()
  await SplashScreen.hide()
  ```

### WebView Debugging
- **iOS**: Safari → Develop → [Device] → [App]
- **Android**: Chrome → `chrome://inspect` → select WebView
- Both require developer mode enabled on the device

### Build Failures After Plugin Install
- Run `npx cap sync` to ensure native dependencies are installed
- iOS: `cd ios/App && pod install`
- Android: Sync Gradle in Android Studio
